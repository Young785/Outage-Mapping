 ✅ 1. Build a Data Adapter Layer (NON-NEGOTIABLE)

Do NOT let your frontend depend directly on Xcel’s format.

Instead:

Xcel ArcGIS → YOUR API (/api/outages) → Your App

Your API should:

fetch Xcel data
normalize it into YOUR format
handle missing fields safely

Example:

function normalizeXcelData(raw) {
  return {
    id: raw.attributes.OBJECTID ?? null,
    customers: raw.attributes.CUSTOMERS ?? 0,
    lat: raw.geometry?.y ?? null,
    lng: raw.geometry?.x ?? null,
    cause: raw.attributes.CAUSE ?? "UNKNOWN",
  };
}

👉 If Xcel changes, you fix ONE place.

✅ 2. Store Raw Snapshots

Every time you fetch data:

store raw response (at least temporarily)
store normalized version

Why this matters:

debugging when things break
training AI later
replaying storms
fallback if API goes down
✅ 3. Add Fallback Mode

If Xcel fails:

The app should still work with:

last known snapshot
test mode data
manual job entry

👉 Your app should degrade gracefully, not die.

✅ 4. Error Monitoring (simple version)

Your API should detect:

failed fetch
empty data
schema mismatch

And log something like:

Xcel data fetch failed
Xcel schema mismatch detected

Even basic logging is enough.

✅ 5. Do NOT Over-Couple to Xcel

Your system should treat Xcel as:

one input source, not the system

Because over time you may add:

customer call data
your own historical outage patterns
weather data
insurance claim zones
your own “known problem areas”

Current issues in Tech View:

1. Door hanger status is wrong
   When marking “left door hanger,” it is showing as “temp power installed.” That needs to be corrected.

2. Remove “door hanger” as a lead source
   I think lead source should only be:

* Call-in
* ArcGIS outage, new or old
* Self-generated

Door hanger should be an action/status, not a lead source. We usually only leave door hangers on self-generated leads or ArcGIS outage leads.

3. Show door hanger visually on the marker
   Instead of making door hanger a separate lead source, please show it visually by adding a square/border around the existing marker:

* Diamond with square/border = self-generated lead where door hanger was left
* Round ArcGIS marker with square/border = ArcGIS lead where door hanger was left

4. Completed jobs should leave the active job queue
   When I mark a job as complete, it currently remains in the job queue. Completed jobs should not stay in the active queue.

5. Click marker to open investigation
   I would like the ability to click a dot/marker and directly open the job investigation screen for that lead.

6. Remove map clutter
   The map is showing too many landmarks, restaurants, waypoints, and other unrelated map items. Please either remove these from the map style or add a toggle to hide/show them. Default should be clean/simple.

7. Clarify Outages tab vs Job Queue tab
   Right now, the Outages tab and Job Queue tab appear to be showing basically the same list. Please explain the current difference.

My expectation:

* Outages tab = all outage/map leads, especially ArcGIS outage data and general map opportunities.
* Job Queue = actionable work queue only.

Job Queue should include only:

* Call-ins
* Self-generated leads
* ArcGIS leads that are marked sold, started, complete, temp power installed, or return for grounding

8. Missing cities in Outages
   Under the Outages tab, many locations are missing city names. Please fix the location/city display where possible.

9. Routing should probably live inside the outage map
   I am concerned that having routing in a separate window will become confusing when there are thousands of dots on the map, especially during storm chaos and 14-hour workdays.

My preference is that routing should be inside the outage map view, not a separate window, unless there is a very strong reason not to do that.

The whole tool needs to be extremely usable and streamlined in the field.
